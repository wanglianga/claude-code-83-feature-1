# 社区助老理发预约上门与公益补贴平台

## 原始需求

建设社区助老理发预约上门与公益补贴平台，可采用 Vue 3、Spring Boot 和 PostgreSQL。社区工作人员为高龄、失能或行动不便老人录入身份、住址、身体状况、是否需要家属在场、理发偏好、上门时间和公益补贴资格。平台根据理发师排班、志愿者陪同、老人风险等级、楼栋距离和工具消毒状态生成预约。理发师上门前需要确认工具、围布、消毒用品和服务包，志愿者负责陪同进门、核对老人状态、记录现场照片和家属授权。若老人临时不适、家属改约、理发师迟到、服务中出现皮肤划伤、老人拒绝付款、补贴资格变化或工具遗漏，平台要把老人、家属、理发师、志愿者、社区和财务放在同一服务单里处理。服务结束后，剪发照片、补贴金额、自费金额、志愿者陪同记录、老人满意度和异常回访进入档案，社区可以按老人风险、理发师和公益资金复盘服务质量。平台还要支持定期巡访名单、老人生日理发、社区活动集中服务和理发师信用管理。对于独居老人，预约不能只看上门成功，还要记录进门安全、老人精神状态和服务后的回访情况，社区才能判断是否需要额外关怀。社区端还可以按楼栋、志愿者和老人健康风险查看服务覆盖，发现长期未预约或连续取消的老人时，自动转给网格员做关怀确认。

## 新增需求（工具消毒失效与交叉感染追溯）· 原始 Prompt

增加工具消毒失效与交叉感染追溯。理发师上门前扫码核验服务包封签、消毒日期、消毒方式、消毒柜编号和责任人；若消毒超过有效期、封签破损、毛巾围布受潮、剪刀剃刀有污渍或工具遗漏，页面不允许直接开始服务，先联系社区改约或启用备用服务包。若老人有头癣、皮肤病、开放性伤口或明确要求使用一次性用品，服务单标记感染风险，工具单独分装并记录用后处理。若已用未达标工具完成服务，或后续老人、家属反馈皮肤瘙痒、红疹、感染，社区按理发师、服务包、工具编号和同日服务记录反查，列出同工具服务的其他老人，通知家属和志愿者，建议就医并记录结果；确认交叉感染或消毒责任的，暂停该理发师上门资格，安排消毒培训和工具复检，派单权重下调。因工具问题取消或改期不算老人违约，不扣补贴；理发师空跑按社区规则认定补偿，若属工具遗漏或消毒失责则由理发师承担。备用服务包使用后要补录消毒记录，未补录前不得再次派单。工具消毒、交叉感染投诉、复检和补偿结果进入服务单、理发师信用和社区公益资金复盘。

## 技术栈与架构

- **前端**：Vue 3 + Vite + Element Plus + Pinia + ECharts（nginx 非 root 镜像托管，反向代理 `/api`）
- **后端**：Spring Boot 3（Java 17）+ Spring Security（JWT）+ Spring Data JPA
- **数据库**：PostgreSQL 16（仅 compose 内部网络访问，不发布宿主端口）

```
浏览器 → frontend(nginx :8080) ──/api──> backend(Spring Boot :8080) ──> db(PostgreSQL :5432)
```

三个服务均带 HEALTHCHECK；后端、前端容器以非 root 用户运行；数据库不暴露到宿主机。

## 快速开始

```bash
cp .env.example .env        # 可选，默认即可用
docker compose up -d --build
```

启动后通过宿主机映射端口访问（验证环境端口由 `CC_PUBLISH_PORT` 注入，默认 3083）：

```bash
docker compose port frontend 8080     # 查看实际映射的宿主端口
# 浏览器打开 http://localhost:<端口>
```

首次启动时后端自动建表并写入演示数据（12 位老人、3 名理发师、历史服务单、异常、回访、关怀任务等）。

停止并释放资源：

```bash
docker compose down          # 保留数据
docker compose down -v       # 连同数据卷一起清理（下次启动重新生成演示数据）
```

## 关键业务流验证（建议按角色依次体验）

1. **建档**：`staff` 登录 → 老人档案 → 录入老人（身份/住址/身体状况/家属在场/理发偏好/上门时间/补贴资格）。
2. **智能派单**：`staff` → 新建预约 → 选老人、日期、时段提交。系统按理发师排班、当日容量、工具消毒状态（48 小时有效）、楼栋距离、常驻楼栋自动匹配理发师；高风险/独居/需家属在场的老人强制匹配志愿者。
3. **上门前确认**：`barber1` → 理发师工作台/服务单详情 → 工具确认（工具、围布、消毒用品、服务包）；有遗漏会自动生成「工具遗漏」异常。
4. **志愿者进门**：`volunteer1` → 服务单详情 → 进门核对（进门安全、老人状态、精神状态、现场照片、家属授权；需家属在场的老人未授权会被拦截）。
5. **服务完成**：`barber1` → 开始服务 → 完成服务（剪发照片入档）→ 自动生成补贴记录（财务待审）、独居老人自动生成服务回访。
6. **评价与收款**：`family` → 家属服务 → 详情页满意度评价（≤2 星自动生成回访）；自费部分由理发师/社区确认收款。
7. **异常协同**：任意角色在服务单详情「上报异常」（老人不适/家属改约/理发师迟到/皮肤划伤/拒绝付款/补贴资格变化/工具遗漏）→ 社区/财务在同一服务单时间线里接手、解决；迟到/划伤/遗漏自动扣减理发师信用分，补贴资格变化可重算费用。
8. **财务审核**：`finance` → 补贴财务 → 发放/驳回补贴，查看月度资金复盘。
9. **公益服务**：`staff` → 公益服务 → 定期巡访登记、生日理发一键生成（全额补贴）、社区活动报名（自动生成 EVENT 服务单）。
10. **复盘统计**：`staff` → 复盘统计 → 按楼栋/志愿者/风险等级查看覆盖，理发师信用与满意度，预警名单；`grid` → 关怀任务 → 关怀确认（可标记需要额外关怀）。
11. **工具消毒失效与交叉感染追溯（本次新增）**：
    - 消毒加封：`staff`/`barber1` → 工具消毒与备用包 → 消毒登记（方式/消毒柜/责任人/新封签/有效期）；可新建上门备用服务包、登记封签破损。
    - 扫码核验拦截：`barber1` → 今日待上门（张桂英）→ 上门前扫码核验，输入封签 `SEAL-LF-20260917-01` 自动回填消毒日期/方式/柜号/责任人；若勾选封签破损/过期/受潮/污渍/遗漏，系统**不允许开始服务**，可「联系社区改约」（不记违约不扣补贴）、取消并标记空跑，或在右侧「社区备用服务包」一键启用完好备用包。
    - 感染风险服务：核验时勾选感染风险（头癣/皮肤病/开放伤口/要求一次性用品）→ 必须工具单独分装并填写用后处理，服务单自动打「感染风险」标并生成专项回访（可在李秀兰历史单查看）。
    - 追溯反查：`staff` → 交叉感染追溯 → 打开钱淑华红疹反馈追溯单：已按理发师/服务包/工具编号/同日服务反查出郑永康 → 一键通知家属（`family2` 可登录查看消息）与志愿者、建议就医 → 记录随访结果（可登记确诊）→ 确认交叉感染/消毒责任：自动暂停理发师资格、信用 -20、派单权重下调、置培训/复检为未完成。
    - 培训复检恢复：`staff` → 工具消毒与备用包 → 对孙理发登记「消毒培训完成」「工具复检通过」→ 恢复上门资格（权重维持下调）。
    - 空跑补偿：赵德柱工具问题取消单 → 社区/财务在服务单详情「认定补偿」：可选公益资金补偿或判定工具遗漏/消毒失责由理发师承担。
    - 备用包补录：`SEAL-LF-SPARE-03` 待补录前，派单核验均判不可用；在工具消毒页对其「补录消毒」后立即恢复可派单。
    - 数据复盘：复盘统计页新增「工具消毒·交叉感染投诉·复检与补偿复盘」（追溯单数、接触/确诊人数、补录数、空跑补偿金额），并展示每位理发师派单权重与资格状态。

## 验证方式（宿主 docker compose）

本项目以「compose 启动健康 + 关键业务流可走通」为验证标准：

```bash
docker compose up -d --build
docker compose ps                          # 三个服务均 healthy
PORT=$(docker compose port frontend 8080 | cut -d: -f2)
curl -s http://localhost:$PORT/ | head -3  # 前端页面
curl -s -X POST http://localhost:$PORT/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"staff","password":"staff123"}'   # 返回 token 即后端+数据库正常
```

## 环境变量（.env）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `CC_PUBLISH_PORT` | `3083` | 宿主机发布端口（仅前端应用发布；数据库/后端不发布） |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | `haircut` / `haircut` / `haircut123` | 数据库（仅 compose 内部网络） |

## 项目结构

```
├── docker-compose.yml          # app(frontend+backend) + db，仅前端发布宿主端口
├── .env.example
├── backend/                    # Spring Boot 后端（多阶段 Dockerfile，非 root + HEALTHCHECK）
│   └── src/main/java/com/community/haircut/
│       ├── config/             # 安全配置、演示数据初始化
│       ├── controller/         # REST API（/api/**）
│       ├── entity|repository/  # JPA 实体与仓库
│       ├── service/            # 智能派单、服务单流转、异常协同、补贴、关怀扫描、统计
│       └── security/           # JWT 登录态
└── frontend/                   # Vue 3 前端（多阶段 Dockerfile，nginx 非 root + HEALTHCHECK）
    └── src/views/              # 工作台/档案/预约/服务单详情/各角色工作台/异常/财务/回访/关怀/公益/复盘
```
